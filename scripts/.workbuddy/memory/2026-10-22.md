## 修掉的 4 个脚本缺陷（重要，避免复发）

1. **PT 取 `summaries.productType` 会拿到占位值 `PRODUCT`** → 提交报 `4000004`。必须取 `items[].productTypes`。已在 `run_mx._real_pt` 与 `_retry_sku.real_pt` 实现。
2. **独立 listing 误发 `parentage_level=child` + `child_parent_sku_relationship`（parent_sku=None）** → 报 `90253`。新增 `build(..., standalone=True)`。
3. **`variation_theme` 照抄 US（多为 ITEM_PACKAGE_QUANTITY）** → MX 子体同值挂不上父体，报 `8801`。已在 build 内强制 `COLOR`。
4. run_mx 独立品分支不打印 issues（14 个 INVALID 全盲）→ 已补。

## 新增工具脚本

- `_retry_sku.py`：按 US SKU 列表秒级重传（不翻全店），自动判父/子/独立 + 真实 PT，`--force-pt` 强制 PT。
- `_verify_mx.py`：批量回验 ASIN/status/ERROR+WARNING 码。
- `_swap_main_img.py --idx N`：主图被判含文字（18027/18320）时把 US 备选图顶到主图位。
- `_diag_invalid.py`：单 SKU 诊断，打印全部 issues。

## 经验

- 新建 MX listing 的 `offers` 会滞后为空，`DISCOVERABLE` 不等于不可售，隔天再看。
- `LAUNDRY_HAMPER` 本次能出 ASIN → 13013 判定是按属性而非按 PT，黑名单机制仍不精确。
- 跑大店脚本 stdout 有缓冲，命令一律加 `python -u`；单条 bash 超过约 2 分钟会被 SIGTERM，长任务用后台跑。
